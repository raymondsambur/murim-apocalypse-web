- **Sects** (`sects.ts`): all `sect` ops (create/join/invite/accept/decline/leave/kick/promote/deposit/motto/disband) with the role permission matrix, validation (name 3-20 chars unique case-insensitive, tag 2-4 letters unique, rank >= 2, 500 gold), invite expiry (5 min), atomic DB transactions, level formula and XP modifier (`xpModifiers` +2%/level, max +20%), entity `tag` = `[TAG]` kept in sync (`onPlayerSync` or touching entities on change), `MeView.sect` via `onBuildMe`, `p.save.sectId` kept consistent (also for offline members: update the DB row when they are offline), sect chat resolver (`ctx.chat.setSectResolver`), queries `sect {id?}` and `sects`, chronicle line on founding via `sim.record`. - **Masters and disciples** (`masters.ts`): NPC master request (from the NPC menu: expose a command path via the existing `master {op:'request', npc}`), player master/disciple flow (request/accept/decline/dismiss/teach), benefits (XP modifier +10% / +15% when the master is online, skill price discount exposed as an exported function `discipleDiscount(p, npcId)` for the shop module), tribute 10% of mission gold (listen to `missionCompleted`), graduation at rank 3, teach cooldown 1 h, persistence in `master_bonds` + `save.masterId` (NPC masters as negative ids), `MeView.master/disciples`, `NpcMenu.disciple` decoration (eligibility + reason), notes to both parties.
- **Friends** (`friends.ts`): `friend` ops (add by name, accept, decline, remove), query `friends` -> `FriendView[]` (online state, level), login/logout notifications to friends, limits (max 50 friends, 20 pending), persistence in a `friends` table.
- **Duels** (`duels.ts`): `duel` ops (challenge with optional stake, accept, decline), distance/state validation (<= 12 tiles, neither in combat, no duelling yourself, stake <= 20% of the poorer player's gold), 30 s expiry, `invite` message of kind `duel`, start through `getServices(ctx).combat.startDuel`.
