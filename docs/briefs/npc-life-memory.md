## Build
1. **Memory of the player** (structured facts, never free text): a record type `{ subject: charId, kind: 'killedBandits'|'savedTown'|'deliveredGoods'|'completedMission'|'failedMission'|'duelWon'|'duelLost'|'sectFounded'|'rankUp'|'gift'|'insult'|'purified'|'sealedHeart'|'diedNearby'..., place: settlementId, magnitude, atWorldHour, weight }` with exponential decay by world time. Two levels: **town memory** (collective, per settlement x player: renown/standing derived from the weighted sum - "they remember you here") and **personal memory** (per NPC x player: only for NPCs who personally interacted - e.g. you talked to them N times, turned in a mission with them, bought from them). Sources: listen to the typed events (`monsterKilled` for bandit/blight kills near a settlement, `missionCompleted`, `playerLevelUp` for rank changes), and chronicle/player records. Persist in your own DB tables via `ctx.db.migrateModule('npcmemory', [...])` (bounded size: cap and prune low-weight records). Expose `getNpcMemory(ctx)` with `townStanding(settlementId, charId)`, `recall(npcId, charId)`, `remember(...)`.
2. **Rumors & gossip**: a rumor `{ id, topic: 'chronicle'|'player'|'local', facts (structured), subjectIds, originSettlement, bornHour, truth (0..1), spread }` created from `SimEvent` chronicle entries (siege, fall of a settlement, faction capture, famine, NPC death/legend rise, heart sealed) and notable player deeds. Hourly (world time) **spread** model operating abstractly over the NPCs of a settlement: gossipy/cheerful/boastful NPCs spread more, stern/gruff less; rumors travel between settlements with caravans/travellers (use `world.roads` + connectivity, with a delay of hours/days proportional to distance, blocked by sieges/Blight roads); each hop may **distort** (details like numbers/names/outcome softened or exaggerated per teller traits; the `truth` value drops), and rumors **expire/fade**. Cap rumor counts. Persist rumors in the DB. Also subscribe (loosely, guarded) to an `npcChat` event the routines engineer emits when two NPCs chat (`{a, b, settlementId}`); when it fires, boost spread between those two.
3. **Dialogue by grammar/tags, no AI**: a library of **handwritten line fragments** in `shared/src/data/dialogue/*.ts`, each with `tags` (role, traits, mood/need, weather, time of day, season, settlement state (siege/famine/festival/fallen), reputation band of the player in this town, topic) and weights, plus **slots** (`{player}`, `{settlement}`, `{rumor.place}`, `{rumor.who}`, `{weather}`, `{trade}`, `{rank}`, `{faction}`...) and simple composition (opener + body + closer, with variety rules to avoid repeating a line within N hours for the same player/NPC). A pure selector `composeLine(ctx)` filters by tags, scores by specificity (more matching tags = better), picks with a seeded RNG, and fills slots. Target **at least 700 distinct fragments** with real wuxia flavour (murim speech, proverbs, sect gossip, Blight dread, weather, prices, harvests, family complaints, boasts, superstitions) across 12 traits x roles x situations, written well (think distinct voices for a gruff guard, a gossipy innkeeper, a scholarly elder, a greedy merchant, a devout shrine keeper, a weary farmer). Include **reactions to the player's standing/deeds** ("You're the one who cleared the Black Wind from the north road...") using memory facts and **topic lines for news** drawn from rumors the NPC knows (with hedging such as "I heard...", "they say..." scaled by `truth`).
4. **NPC menu integration**: greeting text comes from the composer (replace/wrap `ctx.sim.greeting` through your decorator or an additive hook in `npcmenu.ts`); add **additive** `NpcMenu` fields in protocol: `talk?: { topics: { id: string; label: string }[] }` and a query/command path to **ask a topic** ("Any news?", "How is the town?", "Who lives here?", "What do you think of me?", "About the Blight", "About your work") returning composed lines (use an additive `Queries` entry `npcTalk: { args: {id: number; topic: string}; res: { lines: string[] } }` and register it). Build the client UI in `npcDialog.ts`: a Talk tab/section with topic buttons and a small scrolling log of what the NPC said. Keep NPC mood/traits visible as a subtle line ("gruff, weary") in the dialog header.
5. **Town reputation effects** (light): town standing slightly changes shop discounts/refusals? No - keep to dialogue, greetings, and a small flag in `NpcMenu` (`standing?: 'unknown'|'noted'|'welcomed'|'honoured'|'feared'|'despised'`) so the UI can show it.
6. **Tests** (`makeHarness` for system code; plain vitest for pure shared selector code): memory decay and pruning, standing computation, rumor creation from chronicle events, spread and distortion rules with seeded RNG, expiry, caravan delay and blocked roads, selector respects tags/slots/anti-repeat, determinism, coverage test that every tag/slot used in the library is known and every role x trait pair has at least a few lines, persistence round trip, performance bound per hour. `npx tsc -p packages/server` and `npx tsc -p packages/client` must pass; `npx vitest run` green.
