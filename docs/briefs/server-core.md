Build / finish:
1. **config.ts** - env-driven: PORT (3000), HOST, DB_PATH (`./data/murim.db`, create dir), WORLD_SEED (1337), WORLD_HOUR_MS (60000), COOKIE_SECURE (false), SESSION_DAYS (14), NODE_ENV, LOG_LEVEL, SIM_STUB ('1' uses `sim/stub.ts`), ADMIN_USERS (comma list), STATIC_DIR = `dist/client`.
2. **db.ts** - `node:sqlite` `DatabaseSync`, WAL, foreign keys, **versioned migrations list** (`migrations: string[]`, applied in order, tracked in `schema_version`) so later engineers can append. Tables: `users(id, username unique nocase, pass_hash, salt, created_at, banned, last_login)`, `sessions(token_hash pk, user_id, expires_at)`, `characters(id, user_id unique, name unique nocase, level, json, created_at, updated_at, last_seen)`, `kv(key pk, value)`, `pending_rolls(user_id pk, json, rerolls_used)`. Typed repository functions behind an interface (Postgres could replace it later).
3. **auth.ts + http.ts** (Fastify 5): `POST /api/register`, `POST /api/login`, `POST /api/logout`, `GET /api/me`, `POST /api/character/roll`, `POST /api/character/create`, `GET /api/world` (WorldPayload with base64 `terrain`/`objects`, ETag by seed), `GET /api/health`. Types are in protocol.ts. Rules: username 3-20 chars `[A-Za-z0-9_]` case-insensitive unique; password 8-72; scrypt with per-user salt and timing-safe compare; session = 32 random bytes in cookie `murim_session` (HttpOnly, SameSite=Lax, Secure when COOKIE_SECURE, Path=/), store SHA-256 only; per-IP in-memory rate limits on register/login (10/min) plus a generic API limit; JSON body limit 8 KB; security headers (CSP allowing self + ws, nosniff, referrer policy, frame-ancestors none). Serve the built client from `dist/client` with SPA fallback if it exists (not touching `/api` and `/ws`). Character creation: first roll free (`rollCharacter(new Rng(...))` seeded from crypto randomness, persisted in `pending_rolls`), `REROLLS` (3) more allowed; `create` validates name (3-16 chars, `^[A-Za-z][A-Za-z0-9' -]{2,15}$`, no double spaces, unique ignoring case, tiny banned-word list), clamps look with `clampLook`, builds the save with `newCharacterSave` (home settlement = one whose kind is in the origin's `homeKinds`, preferring the starting village id 0; spawn = its `spawn`), inserts the row, deletes the pending roll. One character per account. Errors are `{error: string}` with proper status codes; never leak internals.
4. **net/gateway.ts** - `ws` WebSocketServer on `/ws` sharing the HTTP server; authenticate from the session cookie during upgrade (401 otherwise); one connection per account (new kicks old with CLOSE_REPLACED); parse JSON, 4 KB limit, validate every `C2S` with **zod** (`net/schemas.ts`); invalid -> `{t:'err'}` + strikes, close with CLOSE_RATE on abuse; token-bucket rate limit (40 msg/s, burst 80); 30 s heartbeat; backpressure guard. Dispatch to registered command handlers; unimplemented commands reply `{t:'err', code:'not_implemented'}`.
5. **ctx.ts** - the `GameContext` API from ARCHITECTURE.md (entities, players, send/sendNear/broadcast/notify, markMe, markDirty, command/query/onTick/onHour/onLogin/onLogout/onInteract, now(), rng, world, sim, config, db) with exported `Entity`, `Player`, `EntityStore`, `PlayerStore`. Entities need a typed extension bag (e.g. `ext`) so gameplay modules can attach monster/npc/node state without editing your code. Comment each member briefly.
6. **game/** - runtime (100 ms drift-corrected tick loop, tick-duration monitoring; world-hour scheduler calling `sim.advanceHours(1, now)` every `hourMs` and fanning out SimEvents: chron/settle/blight patches (send a full map if >4000 tiles changed)/time/weather/board events -> `onHour` handlers; `time` broadcast every 5 s; graceful shutdown that saves everything), entities (spatial hash cell 8, `near`, `ver` counters, `toView`), movement (server-authoritative A* with `findPath` over `worldPathGrid`, snapping targets with `nearestWalkable`, step time `STEP_MS / tileSpeed / agilityFactor`, Dir mapping from step (dx,dy): (+1,0)->0 SE, (0,+1)->1 SW, (-1,0)->2 NW, (0,-1)->3 NE, diagonals pick the dominant screen axis; movement blocked while in combat or while an activity runs unless the gameplay module cancels it via a `canMove` predicate list), aoi (per-client known-set diffing -> one `ents` message per client per tick with `add`/`upd`/`del`; self always visible; offline workers visible), players (PlayerStore, login/logout with `hello`, `buildMeView` using `deriveForCharacter` and `xpToNext`, coalesced `markMe`, autosave every 30 s for dirty players, offline workers kept as `online:false` entities only when `save.activity` is set), npcs (entities from `sim.npcs()`, gentle wandering around home, handle `npcDied`/`npcBorn`/`npcMoved`), chat (local radius `LOCAL_CHAT_RADIUS`, world 1 msg/3 s max 200 chars, whisper by exact name, sect stub + exported `chatToSect`, sanitising, profanity mask, mute), persist (world snapshot via `sim.serialize()` to kv every 60 s and at shutdown; restore if seed matches), queries `world`, `chronicle`, `nearbyPlayers`, `player`, `leaderboard`, and the `title` command (<=24 chars). Unregistered queries return `{ok:false, err:'not_implemented'}`.
7. **sim/stub.ts** - small deterministic `Sim` implementation (satisfying `sim/api.ts`) with a few static NPCs per settlement and a trivial clock for tests / `SIM_STUB=1`. `main.ts` loads the real sim via dynamic `import('./sim/index')` normally and the stub when `SIM_STUB=1` or when the module is missing (log which).
8. **main.ts** - boot: config -> db/migrations -> `generateWorld(seed)` -> sim (restore snapshot, optional catch-up capped at 48 h) -> context/runtime -> register every module in `systems/index.ts` (an exported array `systems: Array<(ctx: GameContext) => void>`, empty for now, with a comment on how to add one) -> http+ws listen.
