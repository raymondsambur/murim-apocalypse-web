## Requirements
1. **No CJK characters anywhere the player can see**: HUD, action bar, panels, tooltips, dialogs, toasts, overlays, auth and creation screens, error screens, chat tab icons, minimap/world-map legends, document title, favicon, `index.html`, CSS `content:` strings, mock data. Item, skill, monster, job and talent names are already English; the `glyph` fields in `@murim/shared` data are CJK and must **never be shown** (do not edit shared data; map them on the client).
2. **Icons**: build a small set of consistent **inline-SVG icons** (stroke/fill, currentColor, theme-aware, crisp at 16-32 px) in `src/ui/icons.ts` with a function `icon(name, opts)` and a registry. Cover at least: panel icons (character, bag, skills, missions, jobs, world, social, settings, chat, close, menu), currency (gold coin), stat icons (might, agility, vitality, spirit, insight, fortune), weapon types (sword, blade, spear, staff, fist), item kinds (outfit, accessory/ring, herb, rare herb/ginseng, ore, ingot, hide, fang, meat, grain, cloth, wine, insignia, blight core, spirit dew, healing pill, qi pill, antidote, breakthrough pill, training pill, manual/scroll, cooked meat), skill schools (sword, blade, spear, staff, fist/palm, internal/breath, movement, medicine, poison) and tiers, activity/job icons (herbalist, miner, farmer, blacksmith, alchemist, training), weather and time (sun, moon, cloud, rain, storm, fog, snow), faction emblems (5 simple emblems in faction colours), combat statuses (bleed, poison, stun, slow, guard, buff, rot), settlement status (thriving, stable, struggling, besieged, fallen), rank badges, a game logo emblem (no CJK) and a favicon (inline SVG data URI). Items/skills map from their shared-data `glyph` character or id to an icon via a lookup table (e.g. 劍 -> sword icon) so unknown ones fall back to a generic icon by kind/school/tier colour - **never to the CJK character**.
3. **Action bar and panel headers get English words**: e.g. Character, Bag, Skills, Missions, Jobs, World, Social, Settings, with the hotkey shown ("C", "I", "K", "M", "J", "O", "F"). On narrow screens keep icon + short label or icon-only with an accessible `aria-label` and a tooltip. Panel titles in English.
4. **Canvas text**: if any canvas-drawn text in `render/**` or `art/**` uses CJK (name plates, minimap, fx), report it and make the smallest change needed (or ask the lead to route it to the render engineer) - search with a CJK regex.
5. **Stronger English copy where the CJK was carrying meaning**: tooltips like "Gold", "Qi", "Rank"; the logo area shows "Murim Apocalypse" with an emblem; the error screen "The road is blocked" keeps its text with a generic broken-road icon.
6. **Guard against regressions**: add a vitest that scans all client source files that produce UI (`src/ui`, `src/i18n`, `src/styles`, `index.html`, mock files) and fails if a CJK character appears in a string literal, template literal, CSS or HTML outside an explicit allow-list (e.g. data tables and comments). Also a test that every icon name referenced by the UI exists in the registry and that the glyph->icon map covers every `glyph` used in `@murim/shared` item, skill, monster and job data (monster/job glyphs too if they are shown anywhere).
7. Preserve accessibility (aria labels, focus rings, contrast) and the look (ink-wash dark UI, gold and cinnabar accents). Icons should feel hand-made and cohesive (same stroke width, rounded joins), with rarity colours on item icons.
