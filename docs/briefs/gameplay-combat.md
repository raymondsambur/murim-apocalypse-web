## What to build
Implement GAMEPLAY_SPEC sections 1-3 faithfully:
- **monsters.ts**: population from `world.spawnPoints` (packs, active conditions for blight packs via `sim.blightAt`, level by `levelForDanger` + blight bonus, species by `pickSpecies`, elite chance), safe zones around settlements, respawn timers, AI loop (idle wander / aggro / chase via `ctx.movement.approach` / return home / regen) running only for monsters near players (bounded per-tick work: keep an active set), siege waves for besieged settlements (listen to `ctx.onHour` events `siege`; also reconcile on boot from `sim.state.settlements[i].siegeUntil`), Blight heart bosses (`MONSTERS.lord`; interact with a node entity whose `nodeKind==='heart'` via `ctx.onInteract('node', ...)` returning true only for hearts - the nodes module creates all node entities; match a world heart node to `sim.state.hearts` by x,y), bounty targets via the `monsters` service (`getServices(ctx).monsters`). Monster entities: `kind:'monster'`, `sprite`, `lv`, `hp/maxHp`, `elite`, `name`. Dead monsters become `hidden` then respawn per pack.
- **combat.ts**: the combat manager (start on interact/aggro, assist, flee, per-beat processing every 1000 ms via `ctx.every`, `combat` message to participants with a `CombatView` + events, `cfx` to nearby spectators, sync hp/qi back into `p.save` every beat and `touch` entity hp/state/combatId, end conditions, rewards: XP via `grantXp` (level factor), gold, loot rolls (per participant with >= 10% damage share), equipment and manual drops, `cend` messages, `monsterKilled` events + `sim.recordKill`, kill counters, reputation effects for bandit kills, skill proficiency xp via `applySkillXp` with `fastSchools` talents, consuming potions used in combat (`itemsUsed` -> removeItem), death/respawn (8 s, lose 10% gold, injury stacks via `injuryUntil/injuryStacks`, respawn at `save.lastTown` settlement spawn with 30% HP/Qi, `playerDied` event, `fx death`), out-of-combat regeneration, dead players cannot act. Register the `combat` service (`startDuel`, `inCombat`) in `getServices(ctx)` - duel combats are friendly (copies of fighters, real HP untouched, end at 15% HP, optional stake transfer, no XP, no death) and are invoked by the social module. Register commands `assist`, `flee`, and an `onInteract('monster', ...)` handler. Also handle the `move`/`interact` of a player who is dead or in combat gracefully.
- **progression.ts**: commands `alloc`, `build` (validate with `sanitizeLoadout`; tactics at most 6 rules; allowed shapes only; skill ids must be in the loadout; item ids consumables), `breakthrough` (spec section 3: requirements, `breakthroughChance`, success/failure, `fx breakthrough`, chronicle via `sim.record` for rank >= 3, loadout slots refresh, stat points), `title` is core's - don't touch. Keep saves consistent: after any change `markDirty` + `markMe`.
- Never reimplement damage math: use the shared engine. Use `ctx.rng` and `ctx.now()` only (determinism in tests).
