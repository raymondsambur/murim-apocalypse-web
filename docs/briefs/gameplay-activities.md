## What to build
Implement section 8 completely:
- **State model**: `p.save.activity` (`train | shift | craft`) with `since`/`settled`. Pure settle functions that, given the activity, character data, season and `now`, compute exactly what to grant for the interval `settled..min(now, since+OFFLINE_CAP_MS)` (floor partial units for crafting; carry the remainder by advancing `settled` only by whole units), apply it (items via `addItem`, gold, job XP via `applyJobXp`, cultivation XP via `grantXp` with the spec's training formula and site multiplier, crafted equipment with rarity/affixes), and report what happened. Settling must be idempotent and safe to call any time (login, every 60 s while online via `ctx.every`, `astop`, `onSave`, shutdown).
- **Commands**: `astart` (validate site exists in `world`/settlement `sites`, distance rules, job/recipe requirements, inputs consumed up-front for crafting `qty` 1-20, not in combat, not already busy; sets entity `state` to `meditate`/`work`/`craft` and `touch`es it), `astop` (settle then end; refund nothing for crafts in progress except unfinished units' inputs - define and document), and cancel-on-move: the core `move` command is blocked by the default movement guard while an activity runs - implement the spec's "moving ends the activity (after settling)" by overriding the `move` command (`ctx.command('move', h, {override:true})` which settles+stops the activity, then delegates to `ctx.movement.moveTo` with the same validation the core uses - look at `game/commands.ts`) and removing/adjusting the default guard accordingly. Fighting also ends activities (hook into combat start through `p.combatId` polling or an exported function - the combat engineer is independent, so poll cheaply in your `every` loop and on `interact`).
- **Offline**: on login settle with the offline cap and tell the player what they earned (`notify` summary: items, gold, xp); characters with an active activity stay in the world as `online:false` workers (core handles the entity); when the cap is reached or the bag fills, end the activity, set `save.activity = null`, `markMe`, and make sure the idle worker is removed (see server-core notes).
- **Queries**: `sites {settlement}` -> `SiteView[]` (training bonus on dojos, job per site), `recipes {site}` -> `RecipeView[]` with `canCraft`/`reason` for the calling player (inputs, level, space).
- Season multipliers use `sim.clock().season` (the clock may be a stub in tests). Talent `jobXp` x1.3, origin `jobBonus` x1.2, sect/disciple multipliers apply to training via `grantXp` automatically.
- Safety: bounded work (iterate only players with activities), no exploits (cap, validation of `qty`, server-side time only), idempotent settle, clock skew safe (`now < since` -> nothing).
