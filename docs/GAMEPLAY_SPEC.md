# Gameplay Rules Spec (server behaviour)

Authoritative rules for the gameplay systems (`packages/server/src/systems/**`). Numbers are starting values; tune with tests. All state changes happen on the server; clients only send intents (`protocol.ts`). Constants and pure helpers live in `@murim/shared` — use them, don't duplicate formulas.

## 1. Monsters
- **Population**: for every `world.spawnPoints[i]` keep a *pack* of `packSize` monsters within radius 3 of the point. Family `beast`/`bandit` are always active; family `blight` packs are active only while `sim.blightAt(x,y) >= 25` (otherwise despawned/dormant). Level = `levelForDanger(danger, rng)`, plus `+floor(blight/40)` for blight packs. Species = `pickSpecies(rng, family, level, allowElite)`; allow one elite in a pack when `danger >= 5` with 12% chance.
- **Safe zones**: no spawning or aggro within `settlement.radius + 2` tiles of any settlement (except siege waves). Players cannot be attacked by monsters in safe zones.
- **Respawn**: when a whole pack is dead, respawn it after `60 + danger*8` seconds (cap 300), only if no player is within 12 tiles of the spawn point.
- **Siege waves**: while `settlement.siegeUntil > nowHour`, keep `siegeStrength`-scaled blight monsters (family blight, level by settlement danger) spawned 8-14 tiles outside the settlement gates, marked `siege:{settlementId}`. Despawn them when the siege ends (`SimEvent siege start:false`).
- **Blight Hearts**: each heart node (`nodeKind: 'heart'`) is guarded by a boss "Blight Lord" (`MONSTERS.lord`, level = 30 + strength/5) while the heart is active (`sim.state.hearts[i].strength > 0 && sealedUntil <= now`). Interacting with the heart node starts a boss fight if no boss is currently alive; killing the Lord calls `sim.damageHeart(id, 60, playerName)`; the boss respawns after the heart regrows.
- **Bounty targets**: when a player accepts a `bounty` mission, spawn a unique elite (`target.monster`, level = offer.level, `elite` as in offer) 15-30 tiles from the settlement on passable land; it belongs to that character (`bountyFor`), despawns on abandon/expiry/after 30 minutes. Killing it completes the mission.
- **AI** (every 500 ms for monsters near players only): idle -> wander slightly around home; if an eligible player is within `def.aggro` tiles (halved in fog, +20% at night for beasts, not for dead/offline players and not in safe zones) -> chase (path to an adjacent tile, monster speed ~ 0.9x player base); adjacent -> start combat; if the target gets farther than 14 tiles or 12 s without progress -> return home and heal. Monsters regenerate to full when idle at home.
- **Entity view**: `kind:'monster'`, `sprite` from `MonsterDef.sprite`, `lv`, `hp/maxHp`, `elite` (0/1/2), `name`, `face`, `state`.

## 2. Combat
- A **Combat** has an id, a position, side 0 (players) and side 1 (monsters or the other duelist), and ticks every `COMBAT_BEAT_MS` (1000 ms) using `stepBeat` from shared. Build player combatants with `buildPlayerCombatant(save, entityId, 0)` and monsters with `buildMonsterCombatant(def, level, entityId, 1)`. Never reimplement damage math.
- **Start**: (a) a player `interact`s with a monster: walk adjacent, then start; (b) monster aggro reaches a player. Include all living pack-mates within 6 tiles of the monster on side 1. Fighters get `combatId`, `state:'fight'`, movement locked, facing each other. A player already in combat cannot start another.
- **Assist**: a player within 8 tiles may send `assist {combat}`; up to 5 players per combat; they join side 0 with a fresh combatant.
- **Per beat**: run `stepBeat`; copy hp/qi/status back; send `{t:'combat', c: CombatView, ev}` to each participating player and `{t:'cfx', ev}` to other clients within AOI; update `EntityView.hp`. Persist hp/qi into `save` every beat.
- **Flee**: `flee` command or tactic `flee`: engine decides success; fleeing players leave the combat, keep movement lock for 2 s; if monsters remain they may chase.
- **End**: side 1 dead -> victory: for each monster killed, rewards go to each participant with damage share >= 10%: XP = `monsterStats.xp` x level factor `clamp(1 + 0.1*(mLv - pLv), 0.1, 1.6)` (x0.05 when the monster is >= 10 levels below); gold roll within `gold`; loot rolled per participant from `def.loot` (chance x (1 + fortune/200)); plus equipment drop chance 6% (x2 elite, x4 boss) of tier `clamp(ceil(mLv/8),1,5)` via `makeEquipment(rng, tier, fortune, undefined, boost)`; plus manual drop 1.5% (x3 elite) for a random skill with `tier <= ceil(mLv/10)` that is not yet learned. Items go to the inventory (full -> lost with a warning). Send `{t:'cend', result:'win', reward}`; clear locks; monster entities become `state:'dead'` and are removed after 3 s; call `sim.recordKill`, mission progress hooks, add skill XP, and gain kills counter.
- **Defeat**: all players dead/fled -> `cend lose`. A dead player: `state:'dead'`, `fx death`, after 8 s respawn at `save.lastTown` settlement spawn with 30% HP/Qi; lose 10% of carried gold; `injuryStacks = min(3, stacks+1)`, `injuryUntil = now + 10 min` (stats reduced via `deriveForCharacter`); `deaths++`. Monsters that win go home and heal.
- **Duels**: same engine, `duel:true` in the `CombatView`; fighters are copies and real HP is untouched; ends when one side's hp <= 15% (declare loser dead-in-duel, set both back to normal); no death penalty, no XP; optional gold stake transferred to the winner.
- **Out of combat**: HP regenerates 1% max / 5 s, Qi 3% max / 3 s (standing still in a settlement doubles it). Inn rest (`rest` command at an innkeeper NPC) fully heals for gold = `10 + level*3`, clears injury.
- **Proficiency**: each skill use adds `learnRate` xp (x1.5 if the talent's `fastSchools` includes the skill's school); level up with `skillXpToNext`, max `SKILL_MAX_LEVEL`.

## 3. Character progression
- Kill/mission/training XP -> `save.xp`; while `xp >= xpToNext(level)` and not a breakthrough level: level up (`xp -= need`, `statPoints += statPointsForLevel(newLevel)`, HP/Qi refilled to 60%, `fx levelup`, note). Talents with `xpBonus` and sect/disciple bonuses multiply XP gained.
- At a breakthrough level (`isBreakthroughLevel(level)`, stage 9) XP stops at `xpToNext`; `breakthrough` command requires: full bar, the pill `BREAKTHROUGHS[rank].pill` in inventory, `gold`, `rank < MAX_PLAYABLE_RANK`. Roll `breakthroughChance(rank, spirit, insight)`: success -> level+1, new rank, `statPoints += statPointsForLevel`, loadout slots grow, `fx breakthrough`, chronicle entry (`sim.record`) for rank >= 3; failure -> qi deviation: lose 30% of the XP bar, injury +1 stack for 30 min, pill consumed (30% chance to be saved). Pill and gold are always consumed on attempt.
- `alloc {stat, n}` spends `statPoints` (n validated, integer, >0). No respec in v1 (a "Heaven-Reversing Pill" can come later).
- `build {loadout, stance, tactics}`: validate with `sanitizeLoadout`; tactics at most 6 rules, only allowed condition/action shapes, skill ids must be in the loadout, item ids must be consumables.

## 4. Items and equipment
- Inventory: `INVENTORY_SLOTS` (40) stacks; stackable items merge by `id` up to `ItemDef.stack`; equipment is never stacked and carries a `uid` (unique per character: `c{charId}-{counter}`; counter persisted in the save/kv).
- `equip {idx,id}`: the stack at `idx` must match `id` and be equipment; requirement `tier <= rank + (slot==='accessory'?1:0)`; swap with the current piece (goes to the slot of the moved item). `unequip {slot}` needs a free slot. `use {idx,id}`: consumables outside combat (heal/qi/cleanse), manuals (learn skill; check rank/stat requirements and not already known; consumed), `pill_train` (+xp), breakthrough pills are *not* usable directly. `drop {idx,id,qty}` destroys.
- Derived stats come from `deriveForCharacter`; after any equipment/skill/loadout/stat change recompute and clamp hp/qi; `markMe` + `markDirty`.

## 5. Shops, inns, teaching
- A shop NPC sells `sim.shopFor(npc).items`. Buy price = `ceil(def.value * 1.15 * sim.priceMult(settlementId, id) * repDiscount)`, `repDiscount = 0.95` at rep >= 30 with the NPC's faction, `0.9` at >= 60, `1.1` at <= -30 (refuse service at <= -70). Sell price = `floor(stackValue * sellMult * clamp(priceMult, 0.6, 1.5))`; sell only what the shop type buys (general buys materials/consumables, smith buys equipment/ore/ingots, alchemist buys herbs/pills). Equipment bought is rarity 0. Call `sim.recordTrade`. Quantities integer 1..99.
- `learn {npc, skill}`: NPC must be a master teaching it, player `rank >= req.rank`, stat minimums met, gold `req.gold` (x0.8 if the player's master is this NPC), reputation >= 0 (>= 20 for tier >= 3 skills), not already learned. New skills start at level 1 and auto-fill an empty loadout slot of the right kind.
- `rest {npc}`: innkeeper only, gold per section 2.

## 6. Missions
- Board: `query board {settlement}` returns `sim.board(settlementId)` (+ settlement view). Accept: player must be inside that settlement's radius + 4 tiles, `rank >= minRank`, fewer than `MAX_ACTIVE_MISSIONS`, no duplicate offer; call `sim.takeOffer`; create `ActiveMission {...offer, progress:0, acceptedDay, done:false}`.
- Progress rules: **hunt** - kills matching `target.monster` (or family) anywhere within the owner's AOI; **purify** - kills of blight-family monsters within `target.radius` tiles of `(x,y)`; **defend** - kills of siege monsters belonging to that settlement while its siege is active; **bounty** - the personal bounty elite; **investigate** - reach within 2 tiles of `(x,y)`; **gather** and **deliver** - checked at turn-in against the inventory (items consumed). `progress` counts up to `target.count` and `done` flips true; send `{t:'mission', update}` on change.
- Turn-in `mturnin {id, npc?}`: the mission must be `done` (gather/deliver: have the items), the player must be within 6 tiles of an NPC of role `elder`/`guard`/`master`/`merchant` in the **giving** settlement (deliver: in `toSettlement`). Grant rewards (`xp, gold, rep, items`), `completedMissions++`, call `sim.recordMissionDone(offer, player.name)`, remove. `NpcMenu.turnIns` lists the ids that NPC can complete.
- Expiry: if `expires` (world day) passes and the mission is not done -> removed with a warning note. `mabandon` returns the offer via `sim.returnOffer` and removes personal spawns (bounty target).
- Reputation: `rep.faction` changes `save.reputation[faction]`, clamped -100..100; killing monsters of family bandit gives +1 rep with the faction that controls the nearest settlement and -1 with `blackwind` (min -100).

## 7. Resource nodes and shrines
- Nodes (`herb`, `rareHerb`, `ore`) are `kind:'node'` entities with `nodeKind`. `interact`: walk adjacent, then a 3 s gather action (`state:'work'`, movement locked, cancellable by `stop`/`move`). Yield: herb -> `herb` x1-3 (+ job xp for herbalist), rareHerb -> `herb_rare` x1 (needs herbalist level >= 3), ore -> `ore_iron` x1-3 with 10% `ore_silver` (job xp miner); bonus quantity +1 per 5 job levels, chance of +1 from fortune. The node disappears (entity removed) and respawns elsewhere in the same area after 120-300 s. `fx gather`.
- Shrines (`shrine`): `interact` heals 50% HP/Qi and gives a *Blessing* note (+10% damage vs Blight for 10 min stored as a timed buff in `save`); also `sim.purify(x,y,6,30)`; once per 10 min per player per shrine.

## 8. Activities (offline progress)
All three kinds store `since` (ms epoch of start) and `settled` (ms epoch up to which output was already granted). **Settle** whenever the player logs in, collects/stops, or every 60 s while online; settle at most `OFFLINE_CAP_MS` past `since` (then the activity ends and the player is told).
- `train {site}`: allowed inside any settlement radius; at a `dojo` site XP is x1.5. XP/h = `(12 + 2*insight + spirit)` x site mult x (1 + sectBonus). State `meditate`. Cannot train in combat or with a pending breakthrough bar overflow (XP stops at the cap).
- `shift {site, job}`: site kind must match `JOB_DEFS[job].site`; the player must be within 3 tiles; output per real hour from `shiftYieldPerHour(job, level, seasonMult)` (season from `sim.clock().season` and `SEASON_YIELD`); gold wage, items and job XP (`jobXpToNext`, max `JOB_MAX_LEVEL`, talents with `jobXp` x1.3, origin `jobBonus` x1.2). Items go to the inventory (full -> activity ends). State `work`.
- `craft {site, recipe, qty}`: site kind must match the recipe job (smithy/alchemy lab); `job.lv >= recipe.level`; consumes `inputs x qty` immediately; completes one unit per `recipe.seconds`; grants outputs and job XP as units finish; equipment recipes roll rarity with `rollRarity(rng, fortune, boost = floor(jobLevel/6))` and `rollAffixes`. State `craft`. Query `recipes {site}` returns `RecipeView[]` with `canCraft/reason`.
- `astop` settles and ends the activity. Moving or fighting also ends it (after settling). An active activity keeps the player entity in the world after logout as `online:false` (the runtime does this when `save.activity` is non-null); such entities cannot be attacked or interacted with except for inspection.
- Query `sites {settlement}` lists work sites (`WorkSiteDef`) of a settlement.

## 9. Sects, masters, friends, duels (social)
- **Sects**: `create` needs rank >= 2, 500 gold, unique name (3-20 chars) and a 2-4 letter tag; creator is `leader`. Roles: leader > elder > disciple > outer. Leader: invite/kick/promote/disband/motto; elder: invite/kick outers & disciples; members: leave (leader must promote a successor first or disband), deposit gold to the treasury. Invites expire after 5 min. `join {sect}` requests (leader/elder approves) or open `accept` of an invite. **Sect level** = `floor(sqrt(total member levels)/2)` (max 10) -> members earn +2% XP per sect level (max +20%). Sect chat channel uses the runtime's `chatToSect`. Show `[TAG]` as the entity `tag`. Persist in DB tables `sects`, `sect_members` (append migrations to `db.ts`). Founding a sect adds a chronicle line (`sim.record`, importance 2).
- **Master-disciple**: NPC master: `master {op:'request', npc}` requires no current master, rank <= 2, reputation >= 10 with the NPC's faction, within 6 tiles; accepted immediately; `masterId = -npcId`. Player master: rank >= 3, at most 2 disciples, disciple rank <= 2, invitation flow (`request` by the aspiring disciple, `accept` by the master, with expiry). Benefits: disciple +10% XP from kills/training (+15% while the master is online), -20% skill prices at that NPC; master gets 10% of the disciple's mission gold as tribute (extra, not deducted) and +1 legacy reputation per disciple level-up. `teach {id, skill}`: the master knows the skill at level >= 3 and the disciple meets requirements; learned at level 1; 1 h cooldown per disciple. Graduation when the disciple reaches rank 3: both get a note, the master gains 200 gold and a title ("Master of <name>") once. `dismiss` ends the bond either side.
- **Friends**: `add {name}` creates a pending request (target must exist; online or offline), `accept/decline/remove`; `query friends` returns `FriendView[]` with online state and level; online status changes push a note to friends on login/logout.
- **Duels**: `challenge {id, stake?}` needs both players within 12 tiles, not in combat, not in a safe-zone restriction (duels are allowed everywhere); the target gets an `invite` of kind `duel`; `accept` starts a duel combat; challenge expires in 30 s.

## 10. Persistence and anti-abuse
- Every state mutation calls `markMe(p)` (client refresh, coalesced) and `markDirty(p)` (save). Never trust indices alone: all inventory commands carry the expected item `id` and are rejected if it doesn't match.
- Rate-limit expensive commands (buy/sell/craft/chat) per player; clamp quantities; ignore commands while dead or in combat when inappropriate (shops, crafting, teaching require out of combat and being near the NPC/site: `distance <= 6` tiles).
- No exploit-prone loops: gold sinks (training, rest, repairs later) exist; sell price < buy price always.
